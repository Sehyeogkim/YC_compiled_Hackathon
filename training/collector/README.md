# Private native LIBERO operator collector

Run this **on the GPU host where native LIBERO already runs**, then SSH-forward port 8765. It binds only `127.0.0.1`; do not expose an unauthenticated public proxy. This is separate from `control-ui/` and does not use the factory scene or its 8D actuator controls.

```sh
MUJOCO_GL=egl python training/collector/server.py --cases /workspace/cases.json --out /workspace/werescue/raw --operator jeff
```

On your local computer, use the existing RunPod SSH connection with `-L 8765:127.0.0.1:8765`, then open `http://127.0.0.1:8765`.

Heavy dependencies are lazy: `python training/collector/server.py --help` works without LIBERO installed. Native execution requires the existing LIBERO/robosuite/MuJoCo stack, numpy and Pillow. MP4 export additionally uses `imageio` + ffmpeg; PNG evidence remains available if encoding fails.

## Failure cases

Create `cases.json` with `schema_version: "werescue.collection_cases.v1"`, `suite` (for example `libero_object`), numeric `task_id`, and `cases` list. Each case requires `case_id`, `parent_episode_id`, `initial_state_id`, explicit `split` (`train`, `val`, `test`), `failure_state_ref` and `goal_ref`. References resolve relative to that file. All cases must match the selected suite/task. `failure_state_ref` is a trusted local `.npy` generated by native `get_sim_state()`; numpy pickle loading is disabled.

The goal JSON requires:

- `eef_pos`: three world coordinates in metres.
- `eef_quat`: four XYZW quaternion values.
- `gripper_qpos`: two native finger positions.
- `object_positions`: map of relevant native object names to three world coordinates. Include at least the manipulated object; robot pose alone is insufficient.

Optional predicate tolerances are `eef_tolerance_m` (0.025), `rotation_tolerance_rad` (0.20), `gripper_tolerance_m` (0.015), `minimum_open_width_m` (0.04), `object_tolerance_m` (0.025), `max_joint_speed` (0.15). Choose a previously validated open-gripper, task-resumable goal and keep its provenance. The proximity predicate is a conservative simulator check, not proof that arbitrary goals are resumable or safe on hardware.

## Human workflow

1. Choose saved failure and begin. Native restore occurs before recording; a new episode UUID is created.
2. Hold jog keys/buttons to execute relative OSC 7D actions. W/S = ±X, A/D = ±Y, Q/E = ±Z. R/F, T/G, Y/H rotate. O opens, C closes the gripper. Native gripper is `-1` open, `+1` close.
3. Reach the reference goal; release motion keys, let motion settle, then verify recovery. The independent pose/scene/gripper/velocity checks must pass.
4. **Human retains control.** The marker closes R′ and begins R at the next observation. Complete the task manually.
5. Native LIBERO success automatically finishes and qualifies the episode. Escape/abort, timeout, or success before the recovery marker preserves an unqualified raw episode.

UI action magnitude is 0.25 in native normalized action coordinates; the server limits motion components to ±0.4 and expires motion after 250 ms without renewed commands. No coordinate delta in metres is inferred from these values. This is local simulation control, not a hardware safety system.

## Saved evidence

Each episode folder contains `episode.json`, `frame_XXXXXX.npz` per executed step, two lossless raw camera PNG sequences, terminal images, aggregate `trajectory.npz`, and predicate evidence. The aggregate includes observation state8, dispatched native action7, next state8, simulator state before/after, actuator controls after, wall-relative timestamp, simulation timestamp, phase and task success. Raw camera arrays are kept in native orientation; the operator preview and optional videos rotate 180 degrees for viewing, matching existing native evaluation helpers. Do not train on preview JPEGs/videos without matching checkpoint preprocessing.

After a recovery boundary, `R_prime.npz` and `R.npz` contain the respective frame slices. Videos are optional and show human data collection, **not a trained recovery policy**. Original episodes are never deleted when unqualified.

Physics target frequency is 20 Hz and each environment step advances a native 20 Hz control tick. Rendering/disk/network overhead may slow wall-clock execution; recorded simulation and wall timestamps remain separate. Idle ticks are actual native zero-motion commands with the selected gripper held.

This raw format is deliberately not declared LeRobot-ready. Camera/action alignment, environment/controller revision, native replay and conversion to the pinned LeRobot format must pass before training. Native full simulator states are saved, but hidden controller caches are not serialized; exact restoration/replay still needs verification.
